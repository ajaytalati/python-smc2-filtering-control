\section*{What changed since v1}

The 2026-05-08 v1 of this guide documented an out-of-date config. The
2026-05-09 changes that prompted this v2:

\begin{itemize}[leftmargin=*, itemsep=2pt]
\item \textbf{Filter HMC was 0\,\% accept across 2880 logged tempering
      levels} in the v1 saturated baseline (measured: source
      \texttt{compare\_v15\_julia\_vs\_python/example\_run/}\\
      \texttt{julia\_horizon\_sweep\_2026-05-09/} bench logs;
      cross-tabulation in
      \texttt{TIER\_0\_FINDINGS.md}). Two underlying bugs:
      step size $\varepsilon$ too large and $h_{\mathrm{fd}}$ too
      small (Bug~A); MCMC kernel did not scale by $\lambda$ (Bug~B,
      masked by Bug~A). \emph{Fixed} by porting the filter HMC to
      the framework's generic ChEES path
      (\texttt{parallel\_hmc\_one\_move\_generic!} +
      \texttt{chees\_pick\_L\_generic} in
      \texttt{julia/SMC2FC\_functional/src/Control/GPUControlSMC.jl}),
      passing \texttt{beta = next\_$\lambda$}, with
      $\varepsilon = 0.005$ and $h_{\mathrm{fd}} = 0.01$.
\item \textbf{Fast controller is the new default}
      (\texttt{--ctrl-n-smc 1024 --ctrl-num-mcmc 8}; was 2048 / 16
      in v1). The technical guide v1's "When to deviate $\to$
      shorter wall time" recipe is now the default; saturated
      controller is the deviation.
\item \textbf{New filter-side rejuvenation knobs} that v1 did not
      expose at all: \texttt{--liu-west-a 0.97},
      \texttt{--smooth-resample-bw 1.0},
      \texttt{--gaussian-bridge true},
      \texttt{--h-fd 0.01},
      \texttt{--filter-chees-min/max 4 / 64},
      \texttt{--collect-ctrl-diagnostics true}.
\end{itemize}

Compared to the v1 saturated config, the new defaults at
$T = 28$\,d trade roughly the same wall (19.1 vs 19.5 min) for a
filter HMC that actually works (mean accept 65.5\,\% vs 0\,\%). Full
table in \S\ref{sec:headline}.

\section{The framework: \texttt{SMC2FC\_functional}}

\texttt{julia/SMC2FC\_functional/} is the default Julia framework.
The previous \texttt{julia/SMC2FC/} has been renamed to
\texttt{julia/SMC2FC\_DEPRECIATED\_USE\_FUNCTIONAL/} and is no longer
used by the v1.5 bench. Both the bench's \texttt{Project.toml} and
\texttt{version\_1\_5\_Julia/models/fsa\_high\_res/gpu\_pf.jl} import
\texttt{SMC2FC\_functional} (commits \texttt{4a5c007},
\texttt{9bab259}; numerics bit-identical to the deprecated framework
on the GPU bench). v2 of this guide adds: the bench's filter HMC
also goes through the framework's generic ChEES code path
(\S\ref{sec:filter_hmc_unified}).

\section{Filter-side rejuvenation knobs}
\label{sec:rejuv}

These flags wire in three complementary diversification mechanisms
on the parameter cloud. v1 had none of them exposed; v2 makes them
the default.

\begin{table}[ht]
\centering
\small
\begin{tabular}{lll}
\toprule
flag & value & where it fires \\
\midrule
\texttt{--liu-west-a}        & 0.97 & per-tempering level, between systematic resample and HMC; per-dim Liu--West shrinkage \\
\texttt{--smooth-resample-bw} & 1.0  & per-tempering level; Silverman-bandwidth KDE resample with Liu--West correction \\
\texttt{--gaussian-bridge}   & true & between rolling windows; multivariate Gaussian bridge \\
\bottomrule
\end{tabular}
\caption{New filter-side rejuvenation defaults. All three are ON by
default in v2.}
\label{tab:rejuv}
\end{table}

\noindent
\textbf{Per-dim Liu--West shrinkage} (\texttt{--liu-west-a 0.97}):
$\theta_i \leftarrow a \cdot \theta_i + (1 - a) \cdot \overline{\theta} + \sqrt{1 - a^2} \cdot \sigma_d \cdot \xi$
applied per parameter dimension, between systematic resample and
HMC. Inline implementation in
\texttt{version\_1\_5\_Julia/tools/bench\_smc\_full\_mpc\_fsa\_gpu.jl}
inside \texttt{run\_outer\_smc}. Fall-back; superseded by
smooth-resample when that is on.

\noindent
\textbf{Silverman+KDE+LW smooth resample}
(\texttt{--smooth-resample-bw 1.0}): multivariate kernel-density
resample with bandwidth from Silverman's rule and a coupled
Liu--West correction $a = \sqrt{1 - h_{\mathrm{norm}}^2}$. Math
ported into the bench from
\texttt{julia/SMC2FC\_functional/src/Filtering/Kernels.jl::}
\texttt{smooth\_resample}. When \texttt{smooth\_resample\_bw $>$ 0}
this branch is selected over the per-dim Liu--West.

\noindent
\textbf{Multivariate Gaussian bridge}
(\texttt{--gaussian-bridge true}): between rolling windows, replaces
the identity-copy of the previous-window posterior with a sample
from $\mathcal{N}(\hat\mu, \hat\Sigma_{\mathrm{reg}})$ via
\texttt{Bridge.fit\_gaussian} +
\texttt{Bridge.sample\_from\_gaussian} in
\texttt{julia/SMC2FC\_functional/src/SMC2/Bridge.jl}. Regularised
sample covariance with $10^{-6}$ Tikhonov.


\section{Filter HMC = framework ChEES path}
\label{sec:filter_hmc_unified}

In v1 the filter HMC was a model-specific function
(\texttt{parallel\_hmc\_one\_move!}) in
\texttt{models/fsa\_high\_res/gpu\_pf.jl} with FIXED leapfrog count
and a \texttt{tempered\_grads} closure that did not depend on
$\lambda$. In v2 the filter calls the same generic framework
functions the controller uses:

\begin{itemize}[itemsep=2pt]
  \item \texttt{parallel\_hmc\_one\_move\_generic!} in
        \texttt{julia/SMC2FC\_functional/src/Control/GPUControlSMC.jl}.
        Takes a \texttt{beta::Float64} keyword and computes
        \texttt{vals\_prior + beta * vals\_data} (and the
        corresponding gradient) --- this fixes Bug~B (missing
        $\lambda$-tempering) by construction. Bench passes
        \texttt{beta = next\_$\lambda$} per tempering level.
  \item \texttt{chees\_pick\_L\_generic} same file. Adapts the
        leapfrog count $L$ per tempering level by maximising
        expected squared jump distance per $\varepsilon \cdot L$
        across the candidate list
        $\{4, 8, 16, 32, 64\}$ (filter side; controller list is
        $\{16, \ldots, 512\}$).
\end{itemize}

The bench's call site in \texttt{run\_outer\_smc} now wraps
\texttt{gpu\_log\_density} as a closure
\texttt{log\_density\_fn :: Matrix\{Float64\} -> Vector\{Float64\}}
and passes it to the framework functions. The model-specific
\texttt{parallel\_hmc\_one\_move!} and
\texttt{parallel\_hmc\_one\_move} in \texttt{gpu\_pf.jl} are no
longer called by the bench (left in place, separate cleanup).

\section{Why this config (not bigger, not smaller)}
\label{sec:why}

\paragraph{The filter-HMC tier is now correct, not just larger.}
v1 reached its filter "saturated" tier by setting $N_{\mathrm{smc}}
= 512$ and $K_{\mathrm{per\_chain}} = 1000$ but left the HMC
kernel rejecting 100\,\% of proposals --- so the cloud was kept
alive only by systematic resample. v2 re-enables HMC by porting it
to the framework's working code path; the filter cloud now mixes
each tempering level (61.9--71.4\,\% accept,
Table~\ref{tab:filter_hmc_meas}).

\paragraph{The fast controller is the new default} because it
delivers comparable wall to v1's saturated config
($T = 28$\,d: 19.1 vs 19.5 min) while the filter side does the
extra HMC work. Saturated controller is now an opt-in deviation
(\S\ref{sec:deviate}).

\paragraph{Smaller still leaves the GPU empty.} The historical
$N = 32, K = 200$ default mentioned in v1 stays a footnote: GPU
util $\sim 38\,\%$, controller settles for a weakly-ramped
schedule.

\paragraph{Bigger is still wall-time-infeasible} for now. v1 noted
$N = 1024, K = 4000, n_{\mathrm{anchors}} = 16$ does not produce
log output in 33 min wall. Untouched in v2.

\section{When to deviate from these defaults}
\label{sec:deviate}

\begin{itemize}[leftmargin=*, itemsep=2pt]
\item \textbf{Want the v1 saturated controller back} (richer
$\Phi$ schedule basis, $\sim 4\times$ more wall): set
\texttt{--ctrl-n-smc 2048 --ctrl-num-mcmc 16}. v1's "Why this config"
discussion of the saturated tier still applies, just at the cost
of $\sim 4\times$ wall.

\item \textbf{Want the v1 filter HMC behaviour back} (debugging
purposes only --- this is the broken config): set
\texttt{--num-mcmc 0} to disable filter HMC, OR
\texttt{--hmc-step-size 0.05} to put it back in the 0\,\% accept
regime. Both reproduce the filter posterior collapse measured in
\texttt{TIER\_0\_FINDINGS.md}.

\item \textbf{Want all rejuvenation tricks off} (also debugging):
set \texttt{--liu-west-a 0.0 --smooth-resample-bw 0.0
--gaussian-bridge false}. The cloud will collapse by day $\sim$15
per the no-filter-HMC baseline measurements.

\item \textbf{Need OT rescue} (very low ESS / hard observation
models): set \texttt{--ot-max-weight 0.01} and accept the
$\sim 12\times$ slowdown. v1.5's 3-channel direct-Gaussian
observation model has not needed this so far.

\item \textbf{Want even shorter wall for debug runs}: there is no
"safer" controller tier below 1024 / 8 in current testing. Drop
\texttt{--N-smc} to 64 and \texttt{--K-per-chain} to 200 if
you need a $\sim 30$ s sanity test --- but the filter posterior
is no longer scientifically meaningful at that scale.

\item \textbf{Reproducibility}: always set \texttt{--seed} explicitly.
Default is 42. Keep \texttt{--replan-K 2} unless you specifically
want more or less frequent re-planning.
\end{itemize}
