\section*{The framework: \texttt{SMC2FC\_functional}}

\texttt{julia/SMC2FC\_functional/} is the \textbf{default} Julia
framework. The previous \texttt{julia/SMC2FC/} has been renamed to
\texttt{julia/SMC2FC\_DEPRECIATED\_USE\_FUNCTIONAL/} and is no longer
used by the v1.5 bench. The v1.5 bench's \texttt{Project.toml}
and the model code at
\texttt{version\_1\_5\_Julia/models/fsa\_high\_res/gpu\_pf.jl} both
import \texttt{SMC2FC\_functional} (commits \texttt{4a5c007},
\texttt{9bab259}; numerics bit-identical to the deprecated framework
on the GPU bench).

\section*{Filter-side config (the inner PF)}

\begin{tabular}{lll}

\midrule

\texttt{--K-per-chain}      & 1000       & inner-PF state particles per chain (latent state cloud size) \\

The filter compute scales roughly as $\mathcal{O}(N_{\text{smc}}
\cdot K_{\text{pf}} \cdot T_{\text{steps}})$ per
\texttt{gpu\_log\_density} call. At this config, one filter call is
sub-millisecond; the filter contributes only $\sim$5\% of the bench
wall time. Filter VRAM at this config is $\sim$300\,MB (out of 32\,GB
available).

\section*{Why this config (not bigger, not smaller)}

\textbf{Smaller (the historical default) was leaving the GPU empty.}
The pre-saturation default was \texttt{N=32 K=200 ctrl-n-smc=256
ctrl-num-mcmc=8 ctrl-n-anchors=8}: wall 100\,s, mean GPU util only
38.5\%, the controller settled on a weakly-ramped schedule
($\bar\Phi=0.38$ at stride 21).

\textbf{Bigger ($N{=}1024, K{=}4000, \mathit{ctrl{\text{-}}n{\text{-}}smc}{=}4096,
\mathit{n{\text{-}}anchors}{=}16$) is wall-time-infeasible.} That
config did push VRAM to 30.8\,GiB (94\% saturation) but the JIT-compile
plus first-kernel launch on those buffers did not produce log output
in 33\,min wall time. Future framework engineering (batched OT GPU
kernel; kernel-fusion pass) is needed before that tier is practical.

\textbf{The picked config is the operating point where:} (a) the
controller has enough compute per replan to converge to the strong
``build $B$ then sprint'' Banister-overload ramp-up at long horizon,
and (b) the whole run finishes in under 30\,min wall.

\section*{When to deviate from these defaults}

\begin{itemize}[leftmargin=*, itemsep=2pt]
\item \textbf{Want shorter wall time} (e.g.\ T=14d or T=7d, debug
runs): keep \texttt{--N-smc 512 --K-per-chain 1000} but drop
\texttt{--ctrl-n-smc} to 1024 and \texttt{--ctrl-num-mcmc} to 8. Wall
time drops $\sim 4\times$ at the cost of a weaker schedule.

\item \textbf{Want more VRAM headroom used (memory-bound experiments):}
bump \texttt{--K-per-chain} to 2000. Should land VRAM around
$\sim$10--12\,GiB without blowing the wall time. Compute scales linearly
in $K$ so wall time $\sim$2$\times$. Not yet measured at T=28d --- run
once and check.

\item \textbf{Need OT rescue} (very low ESS / hard obs models): set
\texttt{--ot-max-weight 0.01} and accept the $\sim$12$\times$ slowdown.
The bench will emit a \texttt{@warn} reminding you. Out-of-the-box
v1.5 does \emph{not} need this --- the 3-channel direct-Gaussian obs
model is informative enough.

\item \textbf{Reproducibility}: always set \texttt{--seed} explicitly.
Default is 42. Keep \texttt{--replan-K 2} unless you specifically want
more or less frequent re-planning.
\end{itemize}
